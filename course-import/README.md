# SoundRig Launchpad — RIFF import drafts

Import-ready drafts of **The Launchpad** (8 tracks), converted from Sunny's Google Drive
folder *SoundRig Music Skool* into the shape `POST /api/admin/import` expects
(`parsedCourseSchema` in `src/lib/import/types.ts`).

Source of truth: **`SoundRig Skool - Full Course Content.docx`** (v4.0, 18 June 2026) and the
per-track files in `Skool Courses/`. Those two agree with each other.

## Decisions taken (change these before import if wrong)

**One course per track.** Each track imports as its own Course, so each gets its own
`/courses/<slug>` link to drop at the end of the matching Skool track. The alternative —
one course with 8 modules — would yield a single link and break the Skool loop.

Slugs are generated by the import route from the course title, so
`"Track 1: The Call to Create"` → `/courses/track-1-the-call-to-create`.

**The track quiz is its own final lesson.** The source puts one quiz at the end of each
track, but RIFF attaches quizzes to lessons. A dedicated closing lesson keeps that mapping
exact and avoids a lesson that holds both a quiz and an unrelated action step.

**Action Steps become assignments.** Every lesson's "Action Step" maps to a RIFF assignment,
which matches the course's own instruction to "submit your work in the R.I.F.F. webapp for
instant AI feedback."

**Quizzes were converted to multiple choice.** The source writes them as open questions with
prose answers; `validateCourse()` rejects any question with fewer than 2 options or no marked
correct answer, so conversion was mandatory. **The correct answers are the source's own —
the distractors are drafted and need a subject-matter review before this goes live.**

**Production notes stripped.** `[VIDEO DEMO NOTE: …]` and `[ILLUSTRATION CALLOUT: …]` are
instructions to the CCO and designer, not learner-facing copy. The video files themselves
live in Drive under `Robyn (CCO)/` and should be attached on the Skool side.

Lesson content is plain paragraphs with `**bold**` only — that is all `LessonPlayer` renders.
Toolkit tables were reflowed into prose lines for the same reason.

  "80% of your time marketing"). It was not used. Confirm with Sunny that it can be retired.
- **Track 8's quiz is a single commitment question** ("Are you ready to execute?"), not a
  knowledge check. Kept as-is with a two-option form so it validates.
- **Lesson 1.3 tells artists to use Notion or Trello.** RIFF ships its own Kanban boards
  (`/boards`), so that step could point inward instead. Left as the source has it.

## Importing

Two routes. **The `.docx` files are the normal one.**

### Via the admin dashboard (recommended)

`course-import/docx/*.docx` are generated from the JSON by `make-docx.ts`, laid out in the
conventions `parse-course.ts` recognises (`Course Title:`, `Module N:`, `Lesson N:`,
`1. question`, `A./B./C.`, `Correct Answer: B`, `Question:`/`Answer:` for the action step).

Upload each through **Admin → Import** like any other course document, review it in the
preview, and commit. Regenerate them after editing any JSON:

```
pnpm exec tsx course-import/make-docx.ts     # JSON  → docx
pnpm exec tsx course-import/roundtrip.ts     # docx  → parser, verifies nothing drifted
```

`roundtrip.ts` feeds the generated files back through RIFF's own `extractText` +
`parseCourse` and fails if the title, lesson count, question count or assignment count
differs from the source JSON. All 8 currently pass on the heuristic parser — the worst
case, used whenever `DEEPSEEK_API_KEY` is unset.

**One known loss:** the heuristic parser titles every assignment `"Short-answer questions"`.
The real title is carried inline as the first words of the instructions (`Define Your True
Fan Avatar — Write a one-paragraph…`), so nothing is lost, but the titles want fixing in the
import preview — 24 edits across the 8 tracks. Setting `DEEPSEEK_API_KEY` on Render switches
to the AI parser, which populates assignment titles properly and avoids this.

### Via the API (lossless)

`POST /api/admin/import` with a JSON file's contents verbatim — they are already shaped as
`{ course, sourceFile }`. Needs an authenticated admin session, and skips the preview step.
Use this if the assignment titles matter more than staying in the UI.

### After importing

Courses are created with `isPublished: false`, so each needs publishing in **Admin → Courses**
before learners can reach it — though the direct `/courses/<slug>` link resolves even while a
course is a draft, so links can be tested first. While in Manage, set each track's
**"When this track is finished"** return link to the *next* Skool track to close the loop.

Import each track **once** — the slug is derived from the title, and re-importing appends
`-2`, which would break the published links.
